# ChalNa 전역 현지화(i18n) 설계

- 작성일: 2026-06-02
- 상태: 승인됨 (구현 계획 단계로 전환)
- 범위: 앱 전체를 다국어로 번역하고, 설정 화면에 언어 선택(시스템/한국어/영어/일본어)을 추가한다. 마이그레이션은 모듈 단위로 진행한다.

## 1. 목표 & 성공 기준

목표
- 설정 화면에 "언어" 메뉴를 추가하고 **시스템 · 한국어 · 영어 · 일본어** 중 선택할 수 있게 한다.
- 사용자 노출 문자열 전체(~210–250개)를 한국어(원본) + 영어 + 일본어로 번역한다.
- 설정에서 언어를 바꾸면 **앱 재시작 없이 즉시** 반영한다.

성공 기준 (검증 가능)
1. 설정 → 언어에서 4개 옵션이 보이고, 현재 선택이 체크로 표시된다.
2. 언어를 바꾸면 현재 화면이 즉시 해당 언어로 다시 그려지고(네비게이션 유지), 앱을 재실행해도 선택이 유지된다.
3. ko/en/ja 각각으로 빌드·실행했을 때 모든 화면에서 미번역(한국어 잔존) 문자열이 없다(브랜드 '찰나/ChalNa' 제외).
4. 영상 내보내기 시 오버레이 날짜/시간이 선택 언어 로케일 형식으로 표시되고 글리프 깨짐이 없다.
5. `AppLanguageStore` 단위 테스트(저장 왕복/locale 매핑/system 처리)가 통과한다.

## 2. 핵심 결정 (확정)

| 항목 | 결정 | 근거 |
|---|---|---|
| 언어 집합 | 시스템 · ko(원본/base) · en · ja | 요청 사항 |
| 기술 | String Catalog `.xcstrings` | iOS 18 타깃, Xcode 기본 워크플로우 |
| 토폴로지 | **중앙 카탈로그 1개** (`ChalNa/Resources/Localizable.xcstrings`, main 번들) | SwiftUI `Text`/`String(localized:)`의 기본 조회 번들이 `Bundle.main` 이라, 중앙(main) 카탈로그면 모든 모듈에서 `bundle:` 인자 없이 자동 해석됨. 모듈별은 호출부마다 `bundle:.module`을 강제하고 인프라(8 카탈로그·BundleAccessor·hasResources)도 늘어남 |
| 키 전략 | **한국어 원문 = 키** (String Catalog 기본) | 뷰의 `Text("한국어")`를 그대로 두어 코드 변경 최소화. 단점: 한국어 원문 수정 시 키가 바뀌어 번역 stale 표시(Xcode 감지) |
| 전환 방식 | **즉시 전환**(재시작 없음) | `object_setClass(Bundle.main, …)` 스위즐 + 환경 locale 변경 |
| 번역 출처 | 한국어 원본 + **영어/일본어 초안을 작성자(Claude)가 채움**, 불확실분 표시 후 검수 | 요청 사항 |
| 추가 범위 | Info.plist 권한문 · 영상 오버레이 날짜/시간 · devMock 문구 포함. **브랜드 '찰나/ChalNa'는 전 언어 고정** | 요청 사항 |

> **근거 메모(SwiftUI 번들 동작)**: `Text(LocalizedStringKey)`·`Button`·`String(localized:)`는 기본적으로 `Bundle.main`에서 문자열을 찾는다. 프레임워크/패키지의 리소스는 자동으로 잡히지 않아 `bundle:.module`을 명시해야 한다. 따라서 중앙(main) 카탈로그가 가장 적은 코드 변경으로 전 모듈을 커버한다. 참고: https://blog.eidinger.info/localized-swiftui-views-in-a-swift-package

## 3. 아키텍처

```
ChalNaApp.init()
  ├─ FirebaseApp.configure / prepareDependencies (기존)
  └─ Bundle.setLanguage(저장된 코드)        ← 첫 페인트 전에 스위즐 설치
        │
RootView  @State AppLanguageStore (AppCore)
  ├─ .environment(languageStore)            ← SettingsFeature가 읽기/쓰기
  └─ .environment(\.locale, store.locale)   ← 날짜/숫자 형식 + 라이브 재렌더 트리거
        │
  NavigationStack ─► Text("새 Vlog 만들기")
                       │ LocalizedStringKey → Bundle.main.localizedString(forKey:…)
                       ▼
            [스위즐] LanguageBundle → 선택 언어 <lang>.lproj 로 위임
                       ▼
            ChalNa/Resources/Localizable.xcstrings (ko·en·ja)
```

핵심: SwiftUI는 main 번들을 조회하므로 **중앙 카탈로그가 자동 해석**되고, 스위즐은 "어느 언어의 `.lproj`로 갈지"만 바꿔치기한다.

## 4. 컴포넌트 설계

### 4.1 AppCore (신규 파일)
- `AppCore/Sources/AppLanguage.swift`
  ```swift
  public enum AppLanguage: String, CaseIterable, Sendable {
      case system, ko, en, ja
  }
  ```
- `AppCore/Sources/AppLanguageStore.swift` — `@Observable`
  - `public private(set) var language: AppLanguage`
  - `init()`: `UserDefaults("appLanguage")` 읽어 초기화(없으면 `.system`) 후 `apply()`.
  - `public func set(_ lang: AppLanguage)`: 상태 갱신 + 저장 + `apply()`.
  - `private func apply()`: `Bundle.setLanguage(language == .system ? nil : language.rawValue)`.
  - `public var locale: Locale`: system→`.autoupdatingCurrent`, 그 외 `Locale(identifier:)`.
  - `public static func storedCode() -> String?`: ChalNaApp가 첫 페인트 전 호출할 정적 헬퍼(저장값이 system이면 nil).
- `AppCore/Sources/LanguageBundle.swift`
  - `final class LanguageBundle: Bundle, @unchecked Sendable` — `localizedString(forKey:value:table:)` 오버라이드: associated object에 보관된 `.lproj` 경로가 있으면 해당 sub-bundle로 위임, 없으면 `super`.
  - `extension Bundle { static func setLanguage(_ code: String?) }` — `object_setClass(Bundle.main, LanguageBundle.self)`(1회) + 선택 언어 `.lproj` 경로를 associated object로 설정. `code==nil`이면 경로 nil → 시스템 언어 통과.

### 4.2 앱 셸
- `ChalNa/Sources/ChalNaApp.swift`: `init()`의 `prepareDependencies { … }` 직후 `Bundle.setLanguage(AppLanguageStore.storedCode())` 호출(첫 페인트 언어 보장).
- `ChalNa/Sources/App/RootView.swift`: `@State private var languageStore = AppLanguageStore()` 추가. 루트 컨텐츠에 `.environment(languageStore)` + `.environment(\.locale, languageStore.locale)` 적용.
  - **라이브 재렌더**: `\.locale` 환경 변경으로 `Text` 재평가 유도(네비게이션 스택 유지). 일부 뷰가 갱신되지 않으면 leaf 컨텐츠에 `.id(languageStore.language)` 보조. (검증 항목 — §8)

### 4.3 SettingsFeature
- `ChalNa/Sources/App/AppFeature.swift`: `Path`에 `case language(LanguageFeature)` 추가, 라우터 인텐트(`routerPushedLanguage`) + `destinationView` 분기. (`labelSettings` 패턴 미러)
- `Modules/AppCore/Sources/AppRouter.swift`: `push(.language)` 가능하도록 라우트 enum/핸들러 확장. `RootView.wireRouterHandlers()`에 `routerPushedLanguage` 변환 추가.
- `Modules/SettingsFeature/Sources/LanguageFeature.swift`: 얇은 `@Reducer` 셸(상태 없음, 화면 식별용). 실제 상태는 `AppLanguageStore`(@Observable env).
- `Modules/SettingsFeature/Sources/LanguageView.swift`: `@Environment(AppLanguageStore.self)` 읽어 `AppLanguage.allCases` 리스트 렌더. 현재 선택 체크. 탭 시 `store.set(lang)`. 표시명: system="시스템 설정"(현지화), ko="한국어", en="English", ja="日本語"(endonym 고정).
- `Modules/SettingsFeature/Sources/SettingsView.swift`: `// 향후 메뉴 행…` 위치에 `Divider() + menuRow("언어", subtitle: 현재 언어명) { router.push(.language) }` 추가.

### 4.4 중앙 카탈로그 & 인프라
- `ChalNa/Resources/Localizable.xcstrings` — 키=한국어 원문, ko(원본)/en/ja 값. **작성자가 JSON 직접 작성**(프레임워크 문자열은 타깃별 자동추출이 안 되므로 모듈 스윕으로 수집해 채움).
- `Project.swift` 앱 타깃 Info.plist(`.extendingDefault`)에 추가: `CFBundleDevelopmentRegion = "ko"`, `CFBundleLocalizations = ["ko", "en", "ja"]`.
- 권한문: `ChalNa/Resources/<lang>.lproj/InfoPlist.strings` (ko/en/ja) — `NSPhotoLibraryUsageDescription`, `NSPhotoLibraryAddUsageDescription`.
  - **한계 명시**: OS 권한 다이얼로그는 *기기 언어*를 따른다. 앱 내 언어 오버라이드는 시스템 다이얼로그에 적용되지 않는다(기기 언어가 en/ja인 사용자에게만 해당 번역이 보임). 알려진 제약으로 수용.

## 5. 문자열 마이그레이션 전략

원칙: 키 = 한국어 원문, 중앙 카탈로그.

- **SwiftUI 뷰 (`Text`, `Label`, `.navigationTitle`, `Button` 라벨, `.accessibilityLabel`)**: 대부분 이미 `LocalizedStringKey` 컨텍스트 → **코드 변경 없음**, 키만 카탈로그 등록. (`.accessibilityLabel("뒤로")`도 LocalizedStringKey 오버로드 — 검증)
- **명령형 `String`** (뷰 밖/`String` 타입): `String(localized:)`로 감싼다.
  - Models 열거형/속성: `LabelPosition.koreanName`, `LabelKind.title/subtitle`, `FeedbackCategory.koreanName`, `Film.metaLabel`("CLIPS ·"), `Clip` 라벨, `SampleData`.
  - reducer 조립 문자열: `ExportFeature.statusLine`, MediaPicker 상태(`"\(done) / \(total)"` 등) → `String(localized: "\(x)개")` (format key `%lld`).
  - `LocalizedError.errorDescription`: `ExportError`(CompositionService), `DevMediaError`(PhotosService), `FeedbackError`(SettingsFeature), `PhotoLibraryClient` "알 수 없는 오류".
- **문자열 보간**: `String(localized: "...\(x)...")` 및 `Text("...\(x)...")` 모두 String Catalog format key(`%lld`, `%@`)로 매핑됨.
- **복수형(plural)**: 한국어·일본어는 복수 굴절이 없어 불필요. **영어만** 카운트 문구에 String Catalog "Vary by Plural" 변형 추가(예: `1 film` / `%lld films`).
- **브랜드 고정**: SplashView "찰나"/"ChalNa", Home 헤더의 브랜드 표기 → `Text(verbatim:)`로 변경해 추출/번역에서 제외. `CFBundleDisplayName` 고정.

## 6. 특수 케이스

### 6.1 영상 오버레이 날짜/시간 (픽셀로 박힘 — CATextLayer)
- `ExportFeature`가 선택 언어를 `compositionClient.export(...)`에 `localeIdentifier`(또는 형식 선택)로 전달. `CompositionService`와 `TimelineFeature/AutoLabelsOverlay`가 공통 `OverlayDateFormatter(locale:)`를 사용.
- **형식 결정: 글리프-세이프 숫자 형식**(KERISKEDU 글리프 깨짐 회피)
  - ko/ja: `yyyy/MM/dd`, `HH:mm` (24h)
  - en: `MM/dd/yyyy`, `h:mm a` (12h; AM/PM은 Latin → KERISKEDU 커버)
  - (대안: 年月日 등 완전 idiomatic CJK는 CoreText 폰트 폴백으로 가능하나 KERISKEDU의 일본어 한자 커버리지 **미검증** → 본 스펙은 글리프-세이프 채택. 검증 후 변경 가능.)

### 6.2 UI 날짜/기간 형식
- `FilmDetailView`의 `ko_KR` 고정 `DateFormatter`("yyyy년 M월 d일 EEEE") → `Text(date, format: .dateTime.year().month().day().weekday())`로 교체(환경 locale 추종).
- `SampleData.groupedByDay`의 `"MM.dd"` → 로케일 단축 날짜. (devMock 범위)
- 기간: `"%.1f초"` → `String(localized: "\(v)초")`(en="\(v)s", ja="\(v)秒"). `"MM:SS"`는 숫자라 유지.

### 6.3 폰트
- 시스템 폰트는 로케일 자동 대응. KERISKEDU(오버레이/스플래시)는 Latin/한국어 위주 — §6.1 글리프-세이프 형식으로 일본어 글리프 의존 제거.

## 7. 에러 처리 & 폴백
- 카탈로그 키 누락 → 원본(ko) 자동 폴백(String Catalog 기본).
- 알 수 없는 저장 언어 코드 → `.system`.
- 선택 언어 `.lproj` 부재 → `super`(시스템 언어).

## 8. 테스트 & 검증
- **Swift Testing**(`AppCoreTests`): `AppLanguageStore` 저장 왕복, `locale` 매핑, `system→nil`; `Bundle.setLanguage("en")` 후 알려진 키 해석 통합 확인.
- **시각 검증**(`ios-build-run` 서브에이전트): ko/en/ja 각각 빌드·실행 → 전 화면 스크린샷으로 미번역/레이아웃 잘림/오버레이 글리프 확인.
- **라이브 전환**: Settings에서 언어 변경 → 현재 화면 즉시 재렌더 + 네비게이션 유지 확인(미갱신 시 leaf `.id` 보조).
- **번역 검수**: 불확실한 en/ja 문구 목록화 후 사용자 검수 요청.

## 9. 실행 단위 (모듈별 진행 — 요청 사항)

> 카탈로그는 1개지만 마이그레이션은 모듈 단위로 진행하며, 각 모듈의 키를 중앙 `Localizable.xcstrings`에 누적한다.

0. **기반(Foundation)**: AppCore(`AppLanguage`/`AppLanguageStore`/`LanguageBundle`), `ChalNaApp.init` 스위즐 설치, `RootView` 환경 주입, 빈 중앙 카탈로그 + Info.plist 현지화 키 + `InfoPlist.strings`, `AppFeature.Path.language` + `LanguageFeature`/`LanguageView` + Settings menuRow. → 번역 전이라도 피커·즉시 전환 동작(문구는 한국어 유지).
1. **Models** — 열거형/`Film`/`Clip`/`SampleData` 문자열 `String(localized:)` 래핑.
2. **HomeFeature** — 스윕(대부분 `Text` 무변경) + 키 수집.
3. **MediaPickerFeature** — 스윕 + reducer 조립 문자열 + 접근성.
4. **TimelineFeature** — 스윕 + 접근성 + `AutoLabelsOverlay` 형식(공통 포매터).
5. **ExportFeature** — 스윕 + `statusLine` + export에 locale 전달.
6. **FilmDetailFeature** — 스윕 + 날짜 형식 교체.
7. **SettingsFeature** — 스윕(Support/Label) + `FeedbackError`.
8. **CompositionService** — `ExportError` + 오버레이 날짜/시간 로케일화.
9. **PhotosService** — `DevMediaError` + devMock fixtures.
10. **앱 셸 / Info.plist** — 권한문 + 브랜드 `Text(verbatim:)`.
- 마무리: ko/en/ja 빌드·실행·시각 검증, 불확실 번역 검수 요청.

각 단계 후 `tuist generate`(리소스/Project 변경 시) 및 빌드 그린 확인.

## 10. 비범위 (Out of scope)
- DesignSystem 컴포넌트 내부 문자열(파라미터 구동, 프로덕션 문자열은 `#Preview`뿐) — 호출부에서만 현지화.
- 브랜드명 '찰나'/'ChalNa' 및 앱 표시 이름 현지화.
- 시스템 권한 다이얼로그를 앱 내 선택 언어로 강제(OS 제약).
- RTL/추가 언어(중국어 등) — 현 범위 밖.
